# 运营月报管理需求文档

> 所属模块：运营管理
>
> 需求来源：《某PPP项目一体化智慧运营管理平台建设方案》 §2.3.3；现有可调整原型。
>
> 文档状态：拆分初稿，待业务、权限、数据及接口口径确认。

## 1. 功能

按月填报运营月报，记录工作完成情况、经营收费、问题应对与工作计划。

## 2. 功能说明

运营月报管理是“运营管理”下的独立子模块功能。本功能按一项可独立建设、测试和验收的业务能力拆分，页面、字段、状态、流程和权限在本文件内闭环描述。

主要能力：

1. 按权限查询、查看和维护本功能数据。
2. 在“月报信息”分组维护运营月报正文，提供模板下载、导入和在线编辑正文；查看详情时点击“查看”以 Word 样式窗口展示正文。
3. 上传、查看和归档附件支撑材料。
4. 发起审批并跟踪办理状态、意见和历史记录。

主要业务流程：

1. 填报。
2. 权属企业审核。
3. 城投公司审核。
4. 归档

## 3. 字段说明

系统固定字段沿用平台规范，包括 id、创建人、创建时间、更新人、更新时间、创建部门和创建机构。以下英文字段名为本轮拆分使用的逻辑标识，数据库建模时需统一复核。

### 3.1 应收账款信息

该分组位于基本信息之后、月报信息之前，默认展开。新增、编辑和查看页按下列顺序展示七项系统预填字段；新增、编辑页可人工修改，标题不显示必填星号；金额统一显示为“XX万元”，比例显示为“XX%”。

| 中文字段名     | 英文字段名                     | 数据类型          | 必填 | 说明                                                      |
| --------- | ------------------------- | ------------- | -- | ------------------------------------------------------- |
| 本月已收款项    | monthlyReceivedAmount     | Decimal(18,2) | 否  | 自动汇总关联项目所选月份已确认收款金额；单位万元                                |
| 本年度累计已收款项 | yearReceivedAmount        | Decimal(18,2) | 否  | 自动汇总关联项目当年年初至所选月份末已确认收款金额；单位万元                          |
| 本年度合同额    | yearContractAmount        | Decimal(18,2) | 否  | 从合同台账管理获取对应项目和年度合同额度；单位万元                               |
| 占本年度合同额   | yearReceivedRatio         | Decimal       | 否  | 系统默认按本年度累计已收款项 ÷ 本年度合同额 × 100%计算；字段仅显示比例输入框和“%”，不展示计算公式 |
| 运营期应收金额   | operationReceivableAmount | Decimal(18,2) | 否  | 从政府付款申请获取运营期开始至所选月份末累计应收金额；单位万元                         |
| 运营期已收金额   | operationReceivedAmount   | Decimal(18,2) | 否  | 从费用支付登记获取相同运营期间累计已确认收款金额；单位万元                           |
| 运营期未收金额   | operationUnreceivedAmount | Decimal(18,2) | 否  | 运营期应收金额 − 运营期已收金额；单位万元                                  |

### 3.2 月报信息

详情及编辑页面采用同一页内的可折叠分组，不使用页签导航。“基本信息”和“应收账款信息”默认展开；新增和编辑时“月报信息”默认收起，查看时默认展开。

| 中文字段名 | 英文字段名               | 数据类型          | 长度    | 必填 | 说明                                                                                                          |
| ----- | ------------------- | ------------- | ----- | -- | ----------------------------------------------------------------------------------------------------------- |
| 月份    | reportMonth         | String        | 8     | 是  | 按XX年YY月填写，如2026年09月；一位月份保存时补足两位；用于列表展示和筛选，不自动写入正文模板                                                         |
| 运营月报  | monthlyReportBody   | RichText/HTML | 20000 | 是  | 左侧字段标题、右侧内容操作区，单行展示；下载用户提供的《公司运营月报模板.docx》，支持 DOCX 导入和在线编辑；新建正文保留模板中的公司、年份空白、2025年示例及各项原文，不自动填入项目数据；表单不内嵌正文 |
| 附件    | monthlyAttachment01 | File[]        | -     | 否  | 使用“附件 + 点击上传”行样式，普通文件可多选；允许不上传附件                                                                            |

### 3.3 列表与流程元数据

以下字段用于列表展示及查询。项目名称在既有记录的编辑页面允许维护，保存后同步更新详情和列表；项目及公司信息与关联项目数据保持一致，申请人与流程信息由流程实例产生。

| 中文字段名 | 英文字段名       | 数据类型     | 长度  | 必填 | 说明                                    |
| ----- | ----------- | -------- | --- | -- | ------------------------------------- |
| 项目名称  | projectName | String   | 255 | 是  | 来源于关联项目；编辑时允许修改，保存后同步更新列表和详情          |
| 所属公司  | company     | String   | 255 | 是  | 来源于关联项目所属公司，仅用于本轮查询                   |
| 申请人   | applicant   | String   | 100 | 是  | 流程发起人                                 |
| 提交时间  | submittedAt | DateTime | -   | 条件 | 首次提交时间；暂存未提交显示“—”                     |
| 流程节点  | flowNode    | String   | 100 | 是  | 暂存未提交显示“申请人”；已完成显示“—”；其他状态显示当前或最后所在节点 |
| 状态    | status      | String   | 20  | 是  | 进行中、已终止、已完成、已取消                       |

> 演示数据中“所属公司”统一显示为“示例城投公司”；正式环境仍以关联项目及企业主数据为准。

## 4. 页面布局设计

### 4.1 列表页

- 查询条件按顺序为月份、项目名称、所属公司、申请人、流程状态。
- 所属公司和流程状态使用下拉选择；月份、项目名称、申请人使用文本搜索，月份提示XX年YY月；流程状态选项固定为进行中、已终止、已完成、已取消。
- 操作按钮：新增、查询、重置、刷新；刷新以小图标按钮展示，提供“刷新当前页面”的悬浮提示及无障碍名称。
- 列表列按顺序为项目名称、月份、申请人、提交时间、流程节点、状态、操作，不展示记录编号和更新时间。
- 每条记录操作列提供导出图标，悬浮显示由项目名称、月份和“运营月报”组成的 `.dox` 文件名；原型不实际生成或下载文件，正式导出内容取在线编辑器已保存正文。操作列固定在表格右侧，查看、编辑、导出均为紧凑图标并靠左排列；宽度不足时仅前面的业务列横向滚动，操作列位置固定，窄屏也保留表格横向滚动布局。刷新时保留已经应用的查询条件，总入口嵌入场景仅刷新当前模块页面。
- 提示说明：查询结果为空、无数据权限和接口异常时应给出明确提示。

### 4.2 详情页和编辑页

新增、编辑和详情均在同一页面内按顺序展示“基本信息”“应收账款信息”“月报信息”三个同级可折叠分组，点击标题可展开或收起。基本信息沿用系统自动带入的申请基础信息；应收账款信息展示本次新增的七项自动取数及计算结果。

三个分组标题均居左，字段采用“左侧标题、右侧控件”布局。应收账款信息由系统预填，新增、编辑态为白色可编辑输入框，查看态只读；金额框后显示“万元”，比例框后显示“%”。采用与基本信息相同的三列栅格及标签列间距；宽屏下前四项每行两项时，输入框起点分别与基本信息第1、2列对齐，运营期应收、已收、未收金额位于第1、2、3列同一行；输入框宽度参考项目名称输入框，中屏窄屏自适应换行；各分组内容内边距与现有表单一致。

新增、查看及编辑页面的“月报信息”按顺序展示项目名称、月份、运营月报、附件。项目名称查看时灰色只读，新增及编辑时为白色必填输入框；保存后列表和详情同步更新。月份为必填文本框，按“XX年YY月”填写，如“2026年09月”，不再拆成年度和月份两个字段；查看时只读，输入框尺寸与基本信息中的申请人一致。

必填字段标题前显示紧邻标题的红色星号；截图框选的申请信息字段、应收账款字段及附件不显示星号。标题与控件同行布局，新增、查看、编辑顺序一致。“运营月报”右侧依次提供模板下载、导入、编辑正文；表单不内嵌正文。新增正文使用所提供Word模板的原文、标题空白、2025年示例、下划线及章节结构。在线编辑器的文件名、大纲、页脚及详情窗口均使用月报名称，已保存的正文保持用户内容。导入正文不覆盖单独填写的月份。

附件支持多选且为非必填，可不上传。查看页默认展开基本信息、应收账款信息和月报信息；运营月报和附件分别显示带眼睛图标的“查看”按钮，按需打开Word样式正文窗口或附件列表；无附件时显示“暂无附件”。

新增、编辑页面最底部显示开发补充说明：“点击‘导入’并选择对应的 Word 文件后，系统应将文件正文导入，并在‘编辑正文’中显示导入内容。模板文件位置：PPP/PPP/operations-management/monthly-operation-report/monthly-operation-report-template.docx。”

在上述说明及模板文件路径之后，单独显示标题为“应收账款取数逻辑”的开发备注，文案如下；只读详情页不显示：

> “应收账款信息”中的七项数值由系统按关联项目和所选月份自动取数或计算，并在新增、编辑、查看页面中以可编辑方式展示（查看页只读）。
>
> 1. 本月已收款项、本年度累计已收款项：从费用支付登记模块读取已确认收款数据，分别汇总所选月份的收款金额，以及该年度年初至所选月份末的累计收款金额，自动带入对应字段。
> 2. 本年度合同额、占本年度合同额：从合同台账管理模块获取该项目对应年度的合同额度；比例按“本年度累计已收款项 ÷ 本年度合同额 × 100%”计算后自动带入。
> 3. 运营期应收金额、运营期已收金额：分别从政府付款申请模块和费用支付登记模块获取并汇总，统计期间为项目运营期开始至所选月份末，自动带入对应字段。
> 4. 运营期未收金额：按“运营期应收金额 − 运营期已收金额”计算后自动带入。金额统一按“万元”展示，比例按“%”展示。新增、编辑时应收账款输入框宽度参考项目名称输入框；运营期应收、已收、未收金额在宽屏下同一行展示。

## 5. 交互设计

- 查询条件支持组合筛选，重置后恢复默认范围。
- 提交时间记录首次提交时点，后续编辑不得覆盖；暂存未提交记录显示“—”。
- 流程节点按记录状态展示：暂存未提交为“申请人”，已完成为“—”，进行中显示当前办理节点，已终止或已取消显示结束前最后所在节点。
- 刷新列表前保存当前已应用的查询条件，页面重新加载后恢复查询条件及结果。
- 保存暂存允许保留未完成数据；提交前执行必填、格式、范围及附件校验。
- 正文编辑器提供基础文字格式、字号、对齐和列表工具；编辑后保留正文，表单不内嵌预览。
- 模板下载提供用户给定的原版 DOCX 文件；导入支持 DOCX、既有 Word 兼容 HTML 文档及 HTML/TXT 文件；附件支撑材料为可选项。
- 新增、编辑页面底部展示开发补充说明：点击“导入”选择对应 Word 文件后，将文件正文导入并显示在“编辑正文”中；模板文件位于 `PPP/PPP/operations-management/monthly-operation-report/monthly-operation-report-template.docx`。
- 应收账款信息的七项数值自动带出并允许在新增、编辑时修改；本年度合同额占比及运营期未收金额默认按公式生成，用户可按需编辑，保存时保留当前表单值。
- 表单月报信息以可折叠分组展示，仅出现单行运营月报字段操作区及“点击上传”附件行，不显示具体正文预览；从列表进入查看详情后三个分组默认展开，正文和附件分别由眼睛图标“查看”按钮按需打开。
- 月份校验四位年份及01至12月，一位月份保存时补足两位；月份留空时可暂存，提交时必须填写。
- 锁定或归档记录隐藏编辑入口，详情以只读方式打开。
- 跨模块带出和自动计算字段应展示来源，并禁止人工覆盖。

## 9. 数据权限说明

- 业务经办人默认查看本人创建、本人办理或本人参与项目的数据。
- 权属企业人员按所属公司及授权项目查看数据。
- 城投公司管理人员按管理职责查看授权企业或全部项目数据。
- 跨公司查看、临时授权、离岗交接和历史权限追溯规则待统一确认。

## 10. 数据来源与关联

| 数据项       | 来源模块或系统        | 匹配键              | 更新或回写时点     | 匹配不到的处理       |
| --------- | -------------- | ---------------- | ----------- | ------------- |
| 本功能业务数据   | 本功能填报或维护       | 业务记录ID           | 保存或提交时      | 提示并保留草稿       |
| 关联项目与企业   | 项目信息维护、企业信息维护  | 项目ID、企业ID        | 页面加载及提交校验时  | 禁止提交并提示维护基础信息 |
| 自动带出或汇总数据 | 本功能填报数据及关联业务模块 | 项目ID、业务期间或来源记录ID | 查询、生成文书或归档时 | 显示未匹配并允许返回处理  |

上述应收账款取数规则对应页面新增“应收账款信息”分组的七项数值，按关联项目和月份匹配业务数据。当前原型用演示数值展示自动带出效果，并计算收款比例及未收金额，尚未接入实际业务取数接口；正文导入、编辑和查看沿用现有入口。

## 11. 数据交换与通知

- 运营月报列表操作列提供在线正文 Word 导出文件名提示；原型不实际导出，正式导出内容取在线编辑器已保存正文。
- 涉及批量初始化或计划导入的功能应提供模板下载、逐行校验和错误明细。
- 流程待办、退回、通过、临期和逾期提醒应通过站内消息发送；移动端或外部平台提醒由集成方案确定。

## 12. 异常处理

| 场景          | 系统处理要求             |
| ----------- | ------------------ |
| 关联数据不存在或已停用 | 阻止提交，提示缺失数据及维护入口   |
| 重复提交或重复点击   | 使用幂等控制，不重复生成记录或流程  |
| 自动计算或汇总失败   | 保留原始数据，提示失败原因并允许重试 |
| 审批节点无人可办    | 暂停流转并通知流程管理员，不自动跳过 |
| 附件上传失败      | 明确失败文件，已成功文件不重复上传  |
| 查询或接口超时     | 提示请求失败并允许用户刷新或重试   |

## 13. 验收标准

1. 用户能够按权限进入本功能并查看允许范围内的数据。
2. 页面字段、分组、类型、字典值和只读属性与本文件一致。
3. 暂存、提交、退回、重新提交和归档行为符合状态与操作矩阵。
4. 隐藏编辑入口的只读状态不得通过直接请求绕过服务端权限校验。
5. 金额、比例和日期字段按约定精度及范围校验。
6. 自动带出和汇总数据可定位来源记录，异常时给出可处理提示。
7. 运营月报正文必填，模板下载、导入、编辑和详情弹出的 Word 样式正文窗口均可用；表单不显示正文内容；附件可选上传并保留记录关联关系。
8. 审批意见、节点、办理人和办理时间完整留痕。
9. 五项查询条件能够单独或组合筛选，刷新后保留已应用的查询条件。
10. 操作日志覆盖新增、修改、删除、提交、审批、刷新和接口异常。
11. 已有记录的查看及编辑页面中，“月报信息”的项目名称位于月份字段前；查看态只读，编辑态显示白色必填输入框和红色星号，可修改；保存后列表和详情同步显示新值。
12. 基本信息与月报信息之间展示应收账款信息，七项字段名称、顺序、单位、系统预填可编辑样式和计算结果符合本文定义；比例分母无效时不显示NaN或Infinity。
13. 新增、编辑页底部显示“应收账款取数逻辑”，说明来源、统计期间及两项计算公式；只读详情页隐藏开发备注。独立入口与总入口展示一致。

## 14. 首期边界

- 当前现有原型用于确认页面结构与交互，不代表审批引擎、数据库、权限隔离和外部接口已经实现。
- 正式制式文书、OCR、AI能力、消息渠道、附件存储、接口协议和数据迁移方案需在设计阶段另行确认。
- 本文件未确认的规则不得通过前端默认值固化为业务规则。

## 15. 待确认事项

1. 全部字段的正式必填、长度、精度、字典编码和数据库字段名。
2. 页面按钮与角色的准确对应关系，以及跨公司、跨项目数据范围。
3. 审批节点、审批人、会签方式、退回及撤回规则。
4. 附件格式及大小、消息提醒渠道和时点；Word模板已采用本次用户提供的原件。
5. 本功能与其他模块的数据匹配键、回写时点和异常补偿方式。
6. 用户口径中的“费用支付登记”与本原型现有“费用收款登记”的接口对应关系，以及已确认收款状态、运营期开始日期、年度合同额度的取数字段；分母为零、未匹配到数据及刷新回填的处理规则待接口设计确认。
