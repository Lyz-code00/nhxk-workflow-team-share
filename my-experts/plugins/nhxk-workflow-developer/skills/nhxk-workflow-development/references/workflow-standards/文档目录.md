# 工作流标准文档目录

这是统一资料库，不是技能入口，不承担角色调度。数字员工直接使用自己的 SKILL.md，按当前任务读取相应文档或小节；无需先读本目录，也不要默认加载全部文档。

| 文档 | 用途 | 主要使用者 |
|---|---|---|
| [任务文档与交接标准](任务文档与交接标准.md) | 固定目录、编号顺序、方案落盘、版本与角色交接 | 进入任务或交接时的所有角色 |
| [共同约定](共同约定.md) | 范围、授权、默认模式与角色交接 | 所有角色 |
| [需求契约](需求契约.md) | 业务要点、确认单与验收边界 | 需求；需求审核 |
| [专项需求检查](专项需求检查.md) | 周期数据、自动取数、文书、附件等条件性规则 | 涉及相应能力的角色 |
| [技术设计标准](技术设计标准.md) | 能力评估、数据/接口/流程设计 | 架构；需要补设计的开发；设计审核 |
| [能力地图](能力地图.md) | 当前平台源码与公共契约定位 | 架构、开发；技术审核 |
| [实现与验证清单](实现与验证清单.md) | NORMAL/CUSTOM 分层产物及检查 | 开发；测试准备；代码审核 |
| [测试与留痕标准](测试与留痕标准.md) | 自动化、运行证据与缺陷交付 | 测试；测试审核 |
| [审核标准](审核标准.md) | 审核内容、问题和结论 | 审核 |

本目录定义可复用标准，不保存具体业务的确认结果。实际需求、设计、交付及测试报告放到当前任务产物目录。数据库与代码路径以仓库根为基准，Markdown 引用以当前文件为基准。

分发角色技能时应同时保留 `.agents/skills/` 中所需角色目录及 `.agents/workflow-standards/`，保持两者相对位置。宿主必须允许读取这些文件；只复制单个 SKILL.md 不包含完整参考资料。
