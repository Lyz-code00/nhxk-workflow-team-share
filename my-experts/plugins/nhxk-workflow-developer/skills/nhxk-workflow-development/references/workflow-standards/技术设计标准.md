# 技术设计标准

默认 NORMAL，输入为已确认需求和当前源码。未确认时可分析现状和提出选项，不将假设写成最终方案。

1. 按[能力地图](能力地图.md)定位受影响源码、POM、迁移与实际前端；记录准确路径及读取依据。
2. 将需求与能力逐项对应：`需求编号 | 当前能力及证据 | 缺口 | 推荐实现 | 待确认项`。独立列表、暂存或集成需求需核对支持范围；不能因默认 NORMAL 丢失需求，也不能自动切换 CUSTOM。
3. NORMAL 设计稳定字段键、form-create 配置、校验、变量类型、节点字段权限和模型绑定；复用平台存储，不新建镜像业务表。
4. 已确认 CUSTOM 时设计所属模块、业务表/主键/审计/租户/索引、接口、页面路由、流程绑定；用[实现与验证清单](实现与验证清单.md)的相关部分核对。公共 API 调用与业务事务、重复提交防护、旧事件隔离、详情授权需明确。
5. 涉及自动取数、文书或周期数据时，对照[专项需求检查](专项需求检查.md)相关小节，落实来源接口/匹配键、结构化值与正文关系、单位精度、快照、人工覆盖、异步旧响应防护、导入导出和错误处理；业务口径未决时交还需求确认，不拿模拟值代替真实数据源。
6. 按[任务文档与交接标准](任务文档与交接标准.md)，必须保存 `02-开发方案.md` 和 `03-开发任务清单.md`，更新任务导航；只在聊天中给出方案不算交付。小修改可简写，不能省略落盘。

查库、部署和依赖变更不是分析方案的默认操作。需要改变已确认业务规则、范围或表单模式时，集中提出可比较的方案请用户确认。

## 开发方案必须能指导实施

方案按适用范围写清：

- 需求版本及需求编号、NORMAL/CUSTOM 选择、代码基线、实际前后端仓库与受影响路径、复用能力和能力缺口。
- 字段规格、数据结构与生命周期；CUSTOM 的表/列/索引、审计租户、增量迁移/回退；NORMAL 的 conf/fields、变量类型和保存方式。无关部分标不适用及理由，不强制建表。
- 接口方法/路径、请求响应、校验和权限；页面/组件/路由；外部依赖来源、错误处理、并发和事务策略。
- 流程 key、节点与审批人策略、字段权限、条件变量/默认分支、表单绑定、状态回写、历史与重提；未落实的运行环境 ID 明确标待解析及解析步骤，不能伪造。
- 模型/表单产物位置、部署顺序、环境配置引用、已运行实例兼容、新旧定义切换和回退限制；不把密钥写进文档。
- 每项验收要求对应实现任务、测试层级和通过标准；剩余问题、依赖与风险。

任务清单使用 `任务编号 | 需求编号 | 前置任务 | 仓库/路径 | 实施内容 | 完成标准 | 状态`。按依赖排序，例如先契约与字段设计，再配置/后端，再页面/流程绑定，最后集成、验证与交付；以实际依赖为准，不能简单按人员名称排序。不能只写“完成前端/完成后端”。
