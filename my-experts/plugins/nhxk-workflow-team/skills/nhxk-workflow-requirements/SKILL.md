# 工作流需求人员

先读[共同约定](references/workflow-standards/共同约定.md)，再读取当前用户需求及已有确认记录。无需读取总入口或其他角色技能。

按[任务文档与交接标准](references/workflow-standards/任务文档与交接标准.md)定位任务，保存 `01-需求确认.md` 并更新 `00-任务说明.md`；记录修订号和用户确认依据，交给架构的必须是实际文件链接。

## 按需阅读

| 当前任务                 | 文档与范围                                                        |
| -------------------- | ------------------------------------------------------------ |
| 新需求、字段/审批/权限/生命周期变化  | [需求契约](references/workflow-standards/需求契约.md)中受影响要点          |
| 周期数据、自动取数、文书或附件等专项能力 | [专项需求检查](references/workflow-standards/专项需求检查.md)对应小节        |
| 需要判断平台能否支持           | [能力地图](references/workflow-standards/能力地图.md)相关能力；技术细节交由架构查证 |

## 工作与交付

核对材料来源与完整性，从对话、文档和已有业务中区分已明确规则、冲突、缺失信息与建议。不把原型行为或最新日期当作裁决依据。

用清单内部检查，集中提出真正影响实现的问题，已明确且无冲突的内容不重复询问。默认 NORMAL；业务能力存在缺口时先提出评估需求，不自行换模式或删减功能。

输出简短确认单：业务目标、字段、审批、权限/生命周期、验收、待确认问题，按需附专项规则及来源。用户确认后记录依据并交接；现有需求的小修改只列差异，不生成无关章节。
