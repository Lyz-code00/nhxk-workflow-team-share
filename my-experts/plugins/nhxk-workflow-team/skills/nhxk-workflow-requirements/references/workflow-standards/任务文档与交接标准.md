# 任务文档与交接标准

## 固定位置与排序

用户指定目录时使用该目录；否则统一保存到本后端仓库 `docs/workflow/tasks/<四位序号>-<业务标识>/`。在 `docs/workflow/00-任务索引.md` 登记链接、任务编号、名称、当前阶段和当前修订号。序号从索引和已有目录的最大值递增，创建前检查冲突，不按文件修改时间判断最新任务。不为本标准本身创建虚构的业务任务。

已有任务继续使用原目录，不因换角色或修改需求新建副本。旧目录不符合新命名时先在索引登记实际路径，无需擅自搬迁。用户只给业务名时，先查索引；匹配到多项须集中确认目标，不猜“最近修改”的目录。跨仓库只保存一份权威任务文档，在索引登记实际前后端仓库路径，交接给其他角色时提供绝对目录；不要在前端再复制一份方案。

| 顺序 | 固定文件 | 责任与用途 |
|---|---|---|
| 00 | `00-任务说明.md` | 首个承担任务的角色创建，后续角色更新；导航、阶段、修订与交接状态 |
| 01 | `01-需求确认.md` | 需求人员保存业务要求、验收编号和真实确认依据 |
| 02 | `02-开发方案.md` | 架构师持久化可实施方案，不能只在对话中输出 |
| 03 | `03-开发任务清单.md` | 架构师按依赖排序拆任务；开发记录实际进度 |
| 04 | `04-开发交付.md` | 开发记录文件、配置、检查结果及遗留项 |
| 05 | `05-测试方案.md` | 测试人员保存需求到用例的对应关系和环境前提 |
| 06 | `06-测试报告.md` | 测试人员汇总实际运行结果、版本及证据链接 |
| 07 | `07-审核记录.md` | 审核人员按阶段追加问题、结论和复核结果 |
| 08 | `08-部署与验收.md` | 开发提供部署/回退步骤；获授权的执行人员记录部署与验收结果 |
| 09 | `09-验收报告.md` | 测试人员按需求文档验收标准逐条映射证据，输出最终验收结论 |

编号是查找顺序，不代表必须等测试结束才审核；需求、方案、代码审核均按实际阶段记录。只创建当前阶段需要的文件，未发生的阶段在任务说明中标“未开始”，不生成空报告或假通过。简单修改可在对应文件只写变更内容，但开发方案与任务清单仍须保存。

## 任务说明最小内容

任务编号与名称、范围、当前阶段、当前修订号、需求状态及确认依据、方案状态、适用代码分支/基线、前后端路径；以上各文件的相对链接、阻塞项、下一责任角色及交接条件。没有文件的阶段只标未生成，不写无效链接。

确认需求的修订号、方案引用的需求修订号、任务清单引用的方案修订号必须一致对应。方案状态分“草稿 / 待确认 / 可开发 / 已过期”：架构师在方案完整且关键业务问题已解决后标可开发，不捏造用户审批；仅实现细节不额外增加业务确认环节。

## 角色读取和交接

- 需求：查全局索引和任务说明，保存 `01`，记录用户对当前修订的确认依据；不能把历史确认套给新范围。
- 架构：读 `00 → 01`，核对源码，写 `02 → 03`，更新导航及方案状态；交接必须给出实际文件链接、修订号、阻塞项和首项开发任务。
- 开发：读 `00 → 01 → 02 → 03`，有未解决的相关审核问题再读 `07`。核对已确认需求、可开发方案及引用版本，按依赖顺序实施；缺方案或版本不一致时列明缺口，请架构补齐，不从聊天记录自行拼凑设计。用户明确允许开发兼任架构时，先落盘方案再开发。
- 测试：读 `00 → 01 → 04`，需要技术细节时读 `02`；保存 `05/06` 并关联实际版本、用例和证据。缺陷修复闭环通过后，按需求文档验收标准逐条映射证据，保存 `09-验收报告.md` 并更新任务状态；未覆盖条目如实标注，不写假通过。环境不足可完成方案，不能标运行通过。
- 审核：读 `00` 和对应阶段产物，在 `07` 保存结论、问题编号及证据；结论不等于用户授权发布。
- 部署：读取 `00 → 04 → 06 → 07 → 08` 中已存在且相关的内容，依据授权和实际门槛执行。缺少必要验收证据须明确记录，不把开发完成当上线完成。

## 变更与追溯

文件名保持固定以便定位，正文维护递增修订号与变更记录。已交接的方案发生实质变化时，将原版保存到同目录 `history/<修订号>/`，再更新当前文件；不要覆盖旧确认依据与测试证据。

需求改变时，标受影响方案/任务/用例为待更新；架构更新方案及任务顺序，开发/测试按影响同步。未决项只阻塞依赖它的任务，其余已确认且获授权部分可继续。发现当前源码偏离方案时先记录差异；涉及契约、范围或模式变更必须协调方案，不静默改实现。

各角色结束时更新任务说明与全局索引，交接“当前目录 + 当前修订 + 已完成 + 阻塞 + 下一步”。只在用户授权时发送给其他数字员工，不自行触发调度。
