# 测试与留痕标准

只读当前任务所需小节；编写测试方案时不需要执行全部测试。用例和预期以已确认需求为准。

## 先确定测试范围

- 编写用例/脚本与执行测试分别处理。已有明确授权不重复询问；缺少目标地址、账号角色、租户、可用数据或执行范围时，把方案与问题集中确认。
- 执行浏览器 E2E 需用户明确要求；仅“分析测试方案”不启动浏览器。部署、迁移、服务启动不属于测试默认授权，遵守 RULES.md。
- 明确测试是否会发起真实审批、通知或外部回写，以及允许的数据创建/清理范围。优先隔离测试环境，不猜地址、账号或审批人。
- 环境或权限不足时交付用例、脚本和缺失前提，结果写“未执行/阻塞”，不模拟成功。

## 设计并实现自动化

优先复用目标前端仓库已有 E2E 工具、登录辅助和报告配置；没有工具链时推荐 Playwright，并在安装依赖或变更工具链前明确方案。测试文件放在实际前端测试目录，先读取其 AGENTS.md，编辑前拉取。

从需求生成用例编号、角色、前置数据、步骤、预期结果：

- NORMAL：表单渲染/校验、发起、节点读写权限、审批人待办、通过/驳回/取消、条件分支、详情与历史；仅覆盖模型支持和需求要求的行为。
- CUSTOM：在上述基础上增加已约定的草稿或创建即提交、业务列表、重提、重复提交保护、业务状态回写、旧实例隔离。
- 权限：发起人、审批人、无权限人员与实际启用的租户/数据范围；不要把正常授权的业务查询者误判为非法访问。

使用稳定定位器和条件等待，断言真实业务结果（状态、待办、历史、后端返回），不只检查按钮可点击。并发与过期事件等更适合接口级验证的场景，单独标注层级，不硬塞进 UI 用例。写操作重试前核对是否已经成功，避免重复发起。

## 留痕与报告

每次获授权的运行生成独立 runId（时间+业务标识），复用现有报告位置或使用 `artifacts/workflow-e2e/<runId>/`：

- 运行清单：时间/时区、环境标识、代码版本、需求版本、流程 key/定义版本、工具版本和执行命令（不含密钥）。
- 用例结果：用例编号、预期/实际、通过/失败/阻塞/跳过、耗时、业务记录/流程实例标识与证据相对路径。
- 关键成功步骤截图，失败截图及 trace；视频按需求启用。支持时输出 HTML 报告和机器可读 JSON/JUnit，控制台/网络证据只收集定位故障所需部分。
- 缺陷：复现步骤、影响、预期/实际、关联用例与证据；清理：已清理记录、保留数据及原因。

截图、trace、视频和网络记录可能含个人信息或 Token：使用测试数据，配置脱敏/限制采集；无法脱敏的原始产物存于受限位置，不提交 Git 或自动上传。报告记录保留期限/访问范围；未约定时列为待定，不擅自上传或定期删除。

结束时汇总实际运行数、结果和证据路径；脚本已编写、接口测试通过、浏览器 E2E 通过分别表述。修复后只重跑受影响场景和必要回归，不循环重试掩盖缺陷。

## 专项场景（按确认规则选择）

将需求编号关联用例和证据；未决规则的用例标待确认，不猜预期。重点覆盖周期边界/跨月年/重叠重复、金额单位与舍入、零分母/空值/负值、来源无数据与接口失败、人工改值后刷新、切换关联主体/期间后的旧响应、已归档快照不漂移。

文书覆盖模板原件、导入格式/长度/失败/重复操作、独立字段不被正文导入意外覆盖、正文保存与导出一致、富文本清洗和文件权限；列表覆盖筛选语义、刷新条件保留、数值/正文一致性。审批覆盖草稿和审批中同显示名称但操作不同、退回重提、无人可办、首次提交时间及审计。存在独立/嵌入入口时分别核对实际可用入口；缺少共享原型资源时记录环境阻塞。

将运行清单、用例结果、证据索引和缺陷状态交给审核人员；软件测试留痕与业务系统审批/操作审计是两类要求，不能互相代替。
