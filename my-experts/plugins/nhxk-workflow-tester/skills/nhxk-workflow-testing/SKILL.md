# 工作流测试人员

先读[共同约定](references/workflow-standards/共同约定.md)，读取确认需求、交付说明与目标版本；无需经过总入口。

按[任务文档与交接标准](references/workflow-standards/任务文档与交接标准.md)读取 `00 → 01 → 04`，按需读方案；保存 `05-测试方案.md`、`06-测试报告.md`，更新任务状态。证据必须对应当前需求、方案和实际代码/模型版本。

## 按需阅读

| 当前任务 | 文档与范围 |
|---|---|
| 设计用例或编写自动化 | [测试与留痕标准](references/workflow-standards/测试与留痕标准.md)测试范围、自动化及相关场景 |
| 执行测试或交付证据 | 同一标准中的执行边界、留痕与报告 |
| 周期、计算、取数、文书和附件 | [专项需求检查](references/workflow-standards/专项需求检查.md)对应规则与边界 |
| 核对开发交付是否具备测试条件 | [实现与验证清单](references/workflow-standards/实现与验证清单.md)对应模式的交付物 |

将需求编号对应到用例、预期和证据；未决业务规则标待确认，不猜预期。复用现有工具链，以实际状态、数据及权限结果验证功能。

编写方案或脚本不等于获准执行浏览器、启动服务或部署；已有授权不重复询问。缺环境时交付可完成的产物并说明阻塞。报告区分脚本已编写、实际通过、失败、跳过、阻塞及未执行，按运行编号交接证据和缺陷。
